# Matter records, completion and handoffs

Use existing matter records, not a competing authoritative ledger. The SQLite
register owns structured status/activity. The brief is current working state;
decisions preserve strategic choices and reasons; communications/preferences
preserve future-binding instructions. A chronology holds source-attributed
events. These meanings are host instructions, not new enforced file schemas.

## Preserve meaning

For an approved memory update, read the exact touched section and relevant live
obligations first. Keep the brief concise; move resolved material to dated
history with a source/decision pointer, preserving its substance. Do not prune a
live item without a supported disposition. A wholesale rebuild is a separate
requested task, with an item-by-item accounting of what stayed live, was merged
or was resolved. Do not create a missing brief as an incidental orientation step.

Append strategic choices with alternatives, reasons, date, decision-maker and
source/approval basis. A reversal is a new entry. Append future-binding
communication preferences; supersede them with dated entries rather than
rewriting history. Routine work-completed activity belongs in a proposed
factual Timeline entry, without importing unconfirmed strategy/deadlines.

Use the existing guarded writer appropriate to each artifact. Review the full
diff, current source/target hashes and exact approval. A semantic preservation
check is the host's responsibility; preview tokens do not prove it. No standing
Timeline or memory-write authority is granted. Propose a necessary completion
record when it was not already expressly approved. Avoid duplicating a producing
workflow's record of the same work.

## Leave a resumable result

In an approved record, or the completion response when no record write was
authorized, identify:

- completed work and exact artifact/version, or inline-only delivery;
- actual draft, approved, sent, received, filed, served or executed status, each
  only as supported by evidence;
- controlling source versions and stable message/source locators;
- retrieved/read scope, unread material and remaining coverage gaps;
- completed review, reviewed artifact version, findings/dispositions and pending
  reviewer returns;
- supported next action and actual pending lawyer decision; name an owner only
  if assigned.

Do not treat a task badge or the word "reviewed" as completion evidence. A
receiving session rechecks identity, current artifact/source versions, new
controlling correspondence and transmission state. Reuse unchanged verified
work and refresh affected facts only.

## Review across revisions

Retain the existing manifest, reviewer tasks/returns and collection report paths
in private scratch with the artifact versions they actually reviewed. Keep a
human-readable continuation note of coverage, findings, dispositions and
pending questions when needed; no `review_state` executable is bundled.
Missing retained evidence is a review gap. Never recapture changed bytes and
attribute an old review to them.

Follow the installed panel's new-manifest/review procedure for substantive
corrections. A meaning-preserving edit may be noted as such, but these prose
contracts do not add automatic incremental clearance or override collector
readiness. A material source change reopens affected review; outstanding
material findings, questions or missing sources prevent a ready label.
